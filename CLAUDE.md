# Supervisor for Claude

This is the source repo for Supervisor for Claude, a multi-agent orchestration layer for Claude Code. `pack/` is deployed by `deploy` into `~/.config/claude-supervisor` (run with `claude-supervisor`), or into `~/.claude` with `--global`.

- To deploy, update, or uninstall, follow `docs/deploy.md`.
- To edit agents or skills, follow the `agent-authoring` skill (`pack/skills/agent-authoring/SKILL.md`). Keep the inventory in `docs/architecture.md` in sync with any change to an agent's name, scope, model, or tools.
- Entries in this repo's `.supervisor/` govern work on this repo only. For each decision or rule, decide its reach: repo work (stays in `.supervisor/` or `CLAUDE.md`) or product behaviour (written into `pack/` itself, never left as a pointer to this repo's memory, plans, or docs). Ask the owner when the reach is ambiguous.
- Before deploying, run `python3 -m pytest -q`. The suite covers the deploy tool and lints the pack.
- `deploy` (at the repo root) must stay standard-library-only and compatible with Python 3.9, which is what macOS ships as `/usr/bin/python3`.
- Edits under `pack/` only reach other sessions after `./deploy install`. Deployed agents pick up changes in new sessions.
- `VERSION` holds the pack version and follows the `repo-workflow` `X.y` scheme, with `main` as the default branch. The versioned paths are `pack/` and `deploy`; everything else (`tests/`, `docs/`, `.supervisor/`, `CLAUDE.md`, `README*`, `VERSION` itself) is ancillary. Every commit on `main` that touches a versioned path raises y (normally by one), once per change set, except that the squash-merge commit of a major feature branch sets `X.0` (X raised by one). The agent that lands the change on `main` bumps `VERSION`: the lead in its squash commit, for in-place work the editing agent (under fan-out, the lead or the unit it names, not every worker) before running the tests, or `git-ops` when it commits Mode 2 work (`curator` and `fixer` never commit). `tests/test_version.py` fails on `main` when tracked files under a versioned path differ from `HEAD` and `VERSION` was not raised.
- Feature branches rebase on `main` frequently and never touch `VERSION`. A feature branch that is on `origin` may be force-pushed with `--force-with-lease` after a rebase; `main` is protected and never force-pushed. Before committing or merging into `main`, fetch and `pull --rebase` from `origin` (`repo-workflow` Sync With Origin); push `origin` before `public`, in the same step.
