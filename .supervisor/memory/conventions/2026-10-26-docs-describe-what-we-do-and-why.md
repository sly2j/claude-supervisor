Write docs/ and README prose as what the project does and why. Name something it does not do only when that adds strong information (for example a boundary a reader would otherwise assume is crossed).
Why: lists of absent features pad the text and invite the reader to measure the project against ideas it never adopted.
Rejected: a systematic "what we do not do" section per mechanism.
